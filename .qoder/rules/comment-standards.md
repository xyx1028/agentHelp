# 代码注释三层规范（必须执行）

在本项目编写或修改任何 Python 代码时，必须同步完成以下三层注释，**缺一不可**。
注释使用简体中文，风格与现有代码保持一致（简洁 docstring + 行内 `#`）。
核心原则：注释解释**设计意图与"为什么"**，不复述代码本身。

## 第一层：模块级 docstring（每个 .py 文件必须）

- 文件第一行必须是模块 docstring。
- 必须写清三点：**模块职责 + 在整体架构中的位置 + 核心流程**（一句话或一个有序列表）。
- 禁止只复述文件名（如 `"""工具模块。"""` 这类无信息量写法不合格）。

示例（参照 travel_agent/agent.py）：

```python
"""Agent 编排：模型、工具注册表、记忆门面和会话状态。

一轮问答的核心链路（见 TravelAssistantAgent.ask）：
按作用域加锁 → 加载短期历史 + 召回长期记忆 → LangGraph「assistant ⇄ tools」
循环 → 写回短期窗口并提取长期记忆。模型、工具、记忆均经构造函数注入，可独立替换。
"""
```

## 第二层：类与方法 docstring（必须）

- 所有公开类、公开方法必须有 docstring。
- 逻辑非显而易见的私有方法（如 `_build_graph`、`_call_safely`）同样必须有。
- 内容：**用途 + 关键参数/返回值 + 设计动机**（为什么这样设计，而非做了什么）。
- 特殊情况：LangChain `@tool` 内层函数的 docstring 是给 LLM 阅读的使用说明，
  必须写清**何时调用、传什么参数**，它直接决定模型的工具路由行为。

示例（参照 travel_agent/tools/executor.py）：

```python
@staticmethod
def _call_safely(tool_to_call, arguments, timeout_seconds) -> str:
    """在单线程池中执行工具并限时等待；超时或异常都转为文本而非抛出。

    借助 ThreadPoolExecutor 是因为 LangChain 工具本身没有超时参数；
    超时的工作线程无法被强制杀死，只能取消等待、放弃其结果。
    """
```

## 第三层：关键流程与字段行内注释（必须）

- **多步骤流程**：用编号注释标出步骤（如 `ask()` 中的 `# 1. 读短期历史... # 2. 跑图...`）。
- **解释"为什么"**：防御性判断、兜底分支、阈值与魔法数字、加锁/并发控制、
  Fail Fast 校验等，必须说明动机而非行为。
- **字段与常量**：dataclass 配置字段、模块级常量（正则、URL、关键词表、超时值）
  必须在行尾注释其含义与单位。
- 禁止无信息量注释（如 `# 加 1`、`# 循环列表`）。

示例（参照 travel_agent/config.py）：

```python
tool_timeout_seconds: float = 0.3  # 所有工具的默认执行超时（秒），在执行器层生效
network_tool_timeout_seconds: float = 7.0  # 网络类工具（如天气）专用的执行超时，覆盖默认值
```

## 同步与验收要求

1. 修改代码逻辑时，必须同步更新受影响的三层注释，注释与代码不一致视为缺陷。
2. 新增文件/类/方法必须在同一改动中完成注释，不允许"先写代码后补注释"。
3. 交付前自检：每个新文件有模块 docstring、每个新公开方法有 docstring、
   每处非直觉逻辑有"为什么"注释。
