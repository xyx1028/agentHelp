模块按「数据模型 → 执行器 → 运行编排」三层组织，依赖方向单向向内：
- `models.py` 定义不可变 dataclass（`EvaluationCase`/`EvaluationSuite`/`EvaluationExecution`/`EvaluationResult`/`EvaluationReport`），作为案例描述、原始观测与结构化结果的统一契约。
- `fakes.py` 提供 `MockScenario` 五种离线场景（happy/weather/timeout/error/no-tool），通过 `create_mock_tool_registry` 替换默认工具注册表中的单个工具，并通过 `FakeMessagesListChatModel` 预置两段 AIMessage（一次 tool_call + 一次最终回复）以稳定驱动 LangGraph 的 assistant→tools→assistant 循环。
- `executors.py` 实现 `OfflineToolCaseExecutor`，将每个案例独立装配 registry 与 `AssistantAgent`，抽取 ToolMessage 序列构造 `EvaluationExecution`。
- `runner.py` 暴露 `EvaluationCaseExecutor` Protocol 与 `EvaluationRunner`，把「如何跑一个案例」和「如何断言」解耦；`_collect_failures` 逐项比对实际工具名、observation 子串与 answer 子串；`ConsoleReporter` 负责终端渲染，`run_evaluation` 是 CLI 入口。
- `cases.py` 维护稳定的 `OFFLINE_TOOL_CASES` 与 `DEFAULT_OFFLINE_TOOL_SUITE`，所有案例通过 `scenario`+`city` 参数化复用 fakes。
- `__init__.py` 统一导出公共 API，对外仅暴露 suite/executor/reporter/model/fake 五类符号。
