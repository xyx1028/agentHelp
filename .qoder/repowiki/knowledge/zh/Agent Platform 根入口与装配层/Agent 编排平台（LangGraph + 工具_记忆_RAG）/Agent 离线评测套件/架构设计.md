模块按「数据 → 执行器 → 运行器」三层组织：
- models.py 定义不可变 dataclass（EvaluationCase / EvaluationSuite / EvaluationExecution / EvaluationResult / EvaluationReport），区分「要验什么」「原始观测」「结构化结果」三个语义阶段。
- cases.py 基于 models 组装 DEFAULT_OFFLINE_TOOL_SUITE，覆盖 happy / weather / timeout / error / no-tool 五种 MockScenario 的回归用例。
- fakes.py 提供 create_mock_model 与 create_mock_tool_registry，用 LangChain FakeMessagesListChatModel 预置两段 AIMessage（tool_call + 最终回复）驱动 LangGraph 循环，并通过 ToolRegistry.replace 替换 search_knowledge / get_weather_forecast 以模拟超时、报错、成功路径。
- executors.py 实现 OfflineToolCaseExecutor，构造 AssistantAgent 并抽取 ToolMessage 生成 EvaluationExecution；其 execute(case)→EvaluationExecution 契约由 runner.py 中的 EvaluationCaseExecutor Protocol 暴露，便于注入其他执行后端。
- runner.py 提供 EvaluationRunner（顺序执行 suite → 收集 failures → 产出 EvaluationReport）、ConsoleReporter（终端可读输出）与 run_evaluation 入口（保持 main.py --evaluate 布尔返回契约）。
依赖方向单向：runner → executors/fakes/cases → models；对外仅通过 __init__.py 的 __all__ 暴露公共 API。
