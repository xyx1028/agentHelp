模块按 `__init__.py` 注释声明的单向依赖分层组织：
- models.py：纯数据层，定义 MemoryKind/MemoryOwner/MemoryScope/MemoryRecord/MemoryQuery/RetrievedMemory/MemorySettings 等 frozen dataclass，仅含校验逻辑，不依赖任何实现。
- contracts.py：三个 typing.Protocol（ShortTermMemory / LongTermMemory / LongTermMemoryWriter）作为依赖倒置边界，AgentMemory 只依赖协议而非具体类，便于替换 SQLite/Redis/向量库后端。
- short_term.py：MessageWindowPolicy（裁剪策略）与 InMemoryShortTermMemory（进程内 dict + RLock 按会话隔离）分离，便于单独测试裁剪规则。
- long_term.py：InMemoryLongTermMemory 基于 owner→id→record 的双层 dict，使用中文双字 bigram + 英文整词的正则分词做词面重叠打分，无命中时回退到最新记录。
- writer.py：ExplicitPreferenceWriter 仅匹配「请记住」开头的显式授权消息，经注入关键词过滤后分类为 CONSTRAINT/PREFERENCE/PROFILE，并用 sha256(scope+kind+content) 生成确定性 id 实现幂等覆盖；NoopLongTermMemoryWriter 用于禁用写入。
- service.py：AgentMemory 是对外唯一入口，通过 in_memory() 工厂装配默认实现，并提供 turn() contextmanager 对同一 MemoryScope 串行化读-执行-写流程，避免并发覆盖短期历史；recall_context 将召回结果渲染为带 <remembered_user_data> 标签和不可信声明的 Prompt 片段，长度受 settings.long_term_context_max_characters 预算限制。
依赖方向严格自下而上：models ← contracts ← (short_term, long_term, writer) ← service，外部仅从 memory 包根导入 __all__ 白名单中的符号。
